## §1 模块 ↔ 系统菜单 ↔ 路由

| 模块 | 定位（一句话） | 顶级菜单 | 菜单路径 | 页面路由 | 患者端/其它入口 | 版本 | 现有资料 | SKILL.md |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| （待登记） |  |  |  |  |  |  |  |  |

**填表口径**：

| 列 | 怎么填 | 反例（不许这样写） |
| --- | --- | --- |
| `模块` | 模块**目录名**，与 `{{PRODUCT}}\<模块>\` 完全一致 | 简称 / 别名 ❌ |
| `定位（一句话）` | 这个模块**测什么**，一句话说完 | 「很重要的模块」 ❌ |
| `顶级菜单` | **模块 = 系统里的一个叶子菜单**；这一列填它所在的**顶级菜单**（父菜单）名 | 填成叶子菜单名 / 二级菜单名 ❌ |
| `菜单路径` | 完整层级，用 ` / ` 分隔，如 `药品联动保障 / 缺药登记` | 「在菜单里」 ❌ |
| `页面路由` | 前端路由，如 `/drugStorage` | 完整 URL ❌（环境会换，路由不会） |
| `患者端/其它入口` | 不在后台菜单里的入口：uni-app H5 带 `orgCode` 的 URL、大屏地址、定时任务等；没有写 `——` | 留空 ❌（留空分不清「没有」和「没查」） |
| `版本` | **当前在测的版本号**，如 `2606` / `2606beta3`；一版一行分不清时就写最新在测的那一版 | 留空 ❌ / 用文件时间推 ❌ |
| `现有资料` | 已有的需求原文 / 整理稿 / 造数逻辑 / 报告 / 脚本，**文件名要具体** | 「有一些」 ❌ |
| `SKILL.md` | 模块**索引** + 该版本规范的相对路径，如 `../<模块>/SKILL.md ｜ ../<模块>/skill/<版本>/SKILL.md` | —— |

> **顶级菜单必须实地核**：填表前在环境里**展开菜单树确认**，找不到就问用户；
> **不要照着需求文档的章节名猜菜单名**（文档里的名字常和菜单名不一致）。

## §2 命名规则

| 规则 | 内容 |
| --- | --- |
| **`_` 开头 = 辅助目录** | 如 `_框架配置` `_冒泡测试` `_库结构` `_templates` `_archive` —— **不是模块**，不计入模块数、不登记到 §1 |
| **其余目录才是模块** | `{{PRODUCT}}\<模块>\`，新增模块**不要用下划线开头** |
| **模块名 = `<端>-<逻辑业务对象>`** | **端**（`end`：中心端 / 成员端 / 患者端 …）登记在 `_框架配置\框架登记.json` 的 `ends[]` 里，`default: true` 的那个是**默认端**；**默认端的模块名不带端前缀；非默认端必须带 `<端>-` 前缀**（如 `成员端-缺药登记`）。端前缀写错/该带没带，`test_framework_link` 会报 `E_END_PREFIX` |
| **端内按叶子菜单分目录** | 同一个业务对象在不同端各有一个模块（如 中心端 `缺药登记` / 成员端 `成员端-缺药登记`），各自独立目录、独立报告；**跨端关联要两端都登记**（见 §6） |
| **模块 = 一个叶子菜单** | 这是本框架对「模块」的定义（**父菜单不建目录、只作菜单路径**）；同一顶级菜单下的两个叶子菜单就是两个模块（拆分判据见《需求文档台账.md》§2 判据 C） |
| 模块目录结构 | `SKILL.md`（**索引**：定位 / 公共约定 / 版本索引）+ `skill\<版本>\SKILL.md`（**该版规范**，一版一份，互不覆盖）+ `requirement\`（需求原文，**只读**）+ `final\`（整理稿 / 口径 / `<版本>-<模块>造数逻辑.md`）+ `report\` + `data\` + `scripts\`（按需） |
| 定名要稳 | 模块名一旦登记就**尽量不改**：报告、归档目录、`SKILL.md` 归档索引都按它命名；改名要连带改归档目录 |

> **判断一个 skill 放哪层**（依次往下问）：① 跨**产品**共用 → 框架级 `skills\`（自动加载）；
> ② 只在**本产品**内跨模块共用 → 产品级 `{{PRODUCT}}\_<名字>\`（**本文件所在的 `_框架配置\` 就是这一类**）；
> ③ 只在**单个模块**内成立 → 该模块的 `SKILL.md`。**不要因为"写得很长"就往上放一层。**

## §3 未登记模块的处置

**发现系统里有菜单、但本表里没有** → **先补本表，再开工**：

| 步骤 | 做什么 |
| --- | --- |
| 1 | **停下**当前任务，先确认这确实是「新模块」而不是「已有模块的一个二级菜单」 |
| 2 | 是二级菜单 → 补到已有模块那一行的 `菜单路径` 列 |
| 3 | 是叶子菜单（且父菜单下没有这个模块）→ 建模块目录（复制模块骨架 `SKILL.md`）→ 本表 §1 加一行 → `AGENTS.md` §三 加一行 |
| 4 | 补完后**回读一遍本表**确认没重复登记，再继续原任务 |

**反过来**：表里有、环境里找不到菜单 → 检查是不是**已下线 / 版本未升级 / 权限不足**，
在 `现有资料` 列注明，并**问用户**，**不要**直接删行。
