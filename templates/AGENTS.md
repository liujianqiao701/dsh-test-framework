> **命名规则（用来区分"模块"和"辅助目录"）**：`_` 开头的目录是**框架/产品级辅助目录**
> （`_框架配置` `_冒泡测试` `_库结构` `_templates` `_archive`），**其余才是模块**。新增模块时不要用下划线开头。

> ⚠️ **`.git\` 和 `.dsh\skills` 都不能删**。DSH 找 skill 的方式是
> `findProjectRoot(cwd) + ".dsh/skills"`，而它**只认 `.git` 作为"项目根"标记**：
> - 框架根有 `.git\` → 无论在哪个子目录开会话，都稳定解析到框架根 → 框架级 skill 正常自动加载；
> - **没有 `.git\`** → 探测走到盘根失败后**退回 `cwd`**，于是只有 cwd 恰好是框架根时 skill 才加载，
>   **在产品下的某个模块目录里开新会话，框架级 skill 会静默不加载**。
> - `.dsh\skills` 是指向 `..\skills` 的**目录联接**，删了同样等于框架级 skill 全部消失。
>
> 这个 `.git\` 是 `git init` 出来的空库（**不打算用它管版本**，纯粹当"根标记"用）。
> 据此：**别把框架根做成 git 仓库去提交**（`_archive\backups\` 可能很大，进了历史就麻烦），也**别删 `.git\`**。

**三层结构（越往下越"局部"）**：

| 层级 | 位置 | 自动加载 | 用来放什么 |
| --- | --- | --- | --- |
| **框架级 skill** | `skills\<名字>\SKILL.md` | ✅ 是（按 `description` 自动匹配） | 跨**产品**的通用能力/流程 —— 连库与造数、需求文档读取 + 划掉项核对、看图识图 |
| **产品级规范** | `{{PRODUCT_DIR}}\_框架配置\` | ❌ 否，由本文件 §三 路由 | 一个产品内**跨模块**共享的规范与登记 —— 环境与账密、需求文档台账、模块路由、框架登记.json |
| **模块级 skill** | `{{PRODUCT_DIR}}\<模块>\SKILL.md`（**索引**）+ `<模块>\skill\<版本>\SKILL.md`（**该版规范**） | ❌ 否，由本文件 §三 路由 | 只在**单个模块**内成立的流程 —— 各模块造数逻辑、模块专属踩坑清单。**按版本分开，不揉成一份** |

> ⚠️ **只有框架级 skill 会被自动加载**。产品级/模块级都要**主动去读**
> （`{{PRODUCT_DIR}}\_框架配置\环境与账密.md`、`{{PRODUCT_DIR}}\<模块>\SKILL.md` → 再按它 §8 版本索引进 `skill\<版本>\SKILL.md`）。
> 代价是多一步，好处是长流程规范不会污染其它任务的上下文。

## 二、铁律

1. **开工顺序**：读本文件 → 找到本次属于哪个模块（§三）→ 主动读该模块的 `SKILL.md`；涉及**读需求文档/需求原文/新版需求**先加载框架级 skill **`requirement-docs`**（路径、密码、版本判定、划掉项核对都在那）；涉及**连库/造数**先加载框架级 skill **`db-seeding`**；涉及**看图/截图/图中文字/图表/设计稿/UI 还原度**先加载框架级 skill **`vision-read`**（**模型已原生能读图**：`read_image` 直接看，不用先起桥）；涉及**冒泡测试**再读 `{{PRODUCT_DIR}}\_冒泡测试\冒泡测试规范.md` → 再动手。**登记不完整时不许直接开测**（见 §七 闸门）。
2. **产出不越界**：任何产出物按类型落到本模块的 `requirement/` `final/` `report/` `data/`，**不要丢在框架根目录**。
3. **需求原文只读**：`requirement/` 是业务方给的东西（txt/docx/xlsx），**不要改写**。要提炼、要写自己的理解、要固化口径 → 一律放 `final/`，文件名带 `_AI整理` 或版本号。
4. **报告必须落本模块的 `report/`**：命名 `<模块>-<内容>-<yyyyMMdd>.md`。**怎么写是硬要求（按用户要求"要一目了然，不要密密麻麻一大长篇"）**：① **结论先行** —— §一 结论 + **§二 缺陷速览表在最前**（每条一句话说清哪儿不对 + 严重级 + 需求依据 + 状态），不看下文就知道几条、哪条最严重；② **一条缺陷一小节**，字段固定、**每条 ≤ 20 行**，禁止把多条揉成一段；③ **复现步骤必须清晰可照做**（`1. 2. 3.` 每步一行：打开什么 → 输入点什么 → 看到什么）；④ **每条缺陷必须写「需求原文依据」**（文档名 + 章节号 + **原文引用**）与**「与需求不符点」**（单独一行点明差在哪个字段/分支/文案/口径）——需求确实没写的写 `需求未明确`，**不许拿猜测当依据，也不许因为找不到依据就不写这条**；⑤ 大段日志/接口报文/SQL 结果**不进正文**，落 `data\` 只写路径。模板见 `_templates\测试报告模板.md`。**冒泡测试报告同样按模块**（`冒泡测试-<模块>-<日期>.md`），**不要出全局大报告**；真有多模块问题就每个受影响模块各写一份。
5. **连库/造数按 `db-seeding` 走**（框架级 skill，自动加载）：① 连库前**问清是哪个系统**并核对库地址，连上先用 `host(inet_server_addr())` 自证没连错机器；② 造数前**先查该模块对应版本规范里的造数逻辑**（`skill\<版本>\SKILL.md` §V4 → 模块索引 §8 版本索引）—— **已有的照做，不要重新编，更不要清掉**；③ 确实没有才停下来问用户（不许自己照着表结构编），拿到后写 `<模块>\final\<版本>-<模块>造数逻辑.md` 并**回填该版规范 + 索引 §8**，多版本并存不覆盖；④ 主键一律用 `next_key.py` 动态侦测（按**数值最大**算），**禁止写死**；⑤ **「没有」必须先找过再说** —— 按 本版规范 → 模块索引 §8 → 模块 `final\`/`scripts\` → `_archive\scripts\` 四处处找，都没有才算没有。
6. **碰共享库要留回滚**：改**共享/远程库**之前先快照；改完必须汇报"**改了什么、是否已还原**"。保留还是清理测试数据 **由用户决定**，不要默认留着。
7. **垃圾不入库**：临时脚本、日志、备份、导出文件不进框架根目录；一次性脚本用完移入 `_archive\scripts\`。
8. **新目录只在 §一/§五 允许的位置建**：不要随手在框架根或产品根建新目录 —— 产品根下多一个目录就会被当成一个模块。
9. **模块 `SKILL.md` 是累积型文档，禁止整篇覆盖，且规范按版本分开**（按用户要求"skill 规范要按系统的版本来，一个模块下面区分多个版本，不要所有 skill 融合在一个版本"）：
   - **两层**：`<模块>\SKILL.md` = **索引**（定位 / 公共约定 / **§8 版本索引**），`<模块>\skill\<版本>\SKILL.md` = **该版本的规范**（§V1 基本信息 / §V2 本版需求范围 / §V3 测试要点 / §V4 造数逻辑 / §V5 坑 / §V6 报告）。
   - **一版一份、多版并存、互不覆盖** —— 测下一个版本就**新复制一份** `skill\<新版本>\SKILL.md`，**不要把新版本内容塞进旧版文件**（版本一变口径就变，混在一起必然误用）。
   - 造数逻辑、坑清单、冒泡约定、归档索引都靠往这两层上**追加**。批量套模板的脚本默认**已存在即跳过**，要重建必须显式 `--force` 且先备份。
   - **任何「顺手统一一下格式」的批量操作，先确认不会清掉已经沉淀的内容。**
10. **「看着页面操作流程」必须用 playwright MCP 走真实浏览器**：只要用户要求**看着你操作**（"我看着你点""看着走一遍流程""演示一下""边操作边讲"，含任何同义说法），就**必须**用 playwright MCP（`mcp__playwright__browser_*`）**打开浏览器 + 真实操作页面元素**（导航 / 点击 / 输入 / 切 tab / 翻页 都走真实鼠标键盘），**逐屏推进并同步解说**。禁止用这些"看着像测了"的替代品：只读 DOM 取值、只查接口报文、只写脚本离线跑、只贴截图。浏览器需配成**有头（窗口可见）**，否则"看着"是假的。纯取证（报文落盘 / toast 历史）仍走 `keyword_mcp`，两者**互补不替代**。
11. **需求文档：划掉的不读，但要查**（详见 §三「需求文档读取与划掉项核对」+ 框架级 skill `requirement-docs`）：① **原文只读**，且**先确认是哪一版**（新版本需求也放同一目录，路径不区分版本）；② **加密文档一律先解密**（密码见 §四，**脚本内不留密码**）；③ **文档里删除线 / 修订删除 = 需求已取消，不当需求读** —— 不许拿划掉的内容当"应该有的功能"去提缺陷；④ **但必须单独出「取消项核对表」，逐项到测试环境确认系统里是不是也去掉了**：环境里也去掉了 = 合规；**环境里还留着 = 残留，提缺陷**；查不了 = `无法判定` 并写明缺什么，**不许含糊成通过**。
    - **范围**：需求文档都在**总根目录** `{{REQ_DOC_ROOT}}\`（**一个子目录 = 一个系统**；`find_req_doc.py --list` 可看全部系统与统计）；**划掉规则全系统公用**，不是某个模块的私规。
    - **用户只说"测某系统的某个需求文档"时 → 自己去总根目录定位**：`python skills\requirement-docs\scripts\find_req_doc.py --query "<关键词>" --system <系统>`（或主入口 `prep_requirement.py --system <系统> --find "<关键词>"`），**不许凭记忆猜路径**；命中多份时默认取**主线**那份并把依据写进报告。
12. **该看图就必须看 —— 不读图 = 漏检**：**模型已原生具备视觉能力**（框架自带 `read_image`，秒级、无外部依赖）。① **浏览器每走完一屏，截图后自己读一遍再决定下一步**，不许只存档；② **UI/视觉类问题只能靠图**（错位、重叠、遮挡、截断、列宽、换行、颜色、字号、图标、图表形状与图例、原型图对照、弹窗文案）—— DOM 里这些全是"正常"；③ **但事实要分级**：视觉事实**截图即证据**；**数值/金额/编码/单号/ID/图表数值不可只凭读图**，一律回 DOM / 接口报文 / 日志 / SQL，图只作旁证。报告里写清**依据通道**。识图桥降级为**备用 + 交叉核对**。详见 §三「看图识图」+ 框架级 skill `vision-read`。

## 三、模块路由

做某个模块的任务时，**先读该模块的 `SKILL.md`**：

> 📄 **读任何模块的"需求原文"之前**，先加载框架级 skill **`requirement-docs`**（自动加载）——
> **所有系统的需求文档都在同一个总根目录** `{{REQ_DOC_ROOT}}\`（**一个子目录 = 一个系统**），
> **加密与否逐个判、密码见 §四**。里面有**定位脚本、版本判定、解密脚本、以及"划掉项要回头核对"的规矩**（见下方「需求文档读取与划掉项核对」）。
> **用户只说"测某系统的某需求文档"时，自己去总根目录定位**（`find_req_doc.py --query "<关键词>" --system <系统>`），**不要凭记忆猜路径**。

| 模块 | 定位 | 现有资料 |
| --- | --- | --- |
| （待登记） | | |

> ⚠️ **新增模块必须在 §三 登记一行，不登记 = 会话里读不到它** —— 模块级 `SKILL.md` 不被自动加载，
> §三 是它唯一的入口。登记同时同步 `{{PRODUCT_DIR}}\_框架配置\模块路由.md`。

> 三列怎么填：`模块` = 目录名（不带 `_` 前缀）；`定位` = 一句话业务边界 + 菜单/路由 + 主表；`现有资料` = 需求原文 / 造数逻辑 / 脚本 / 报告。

### 跨模块规范 · 连库与造数（框架级 skill `db-seeding`）

**自动加载**（说"连数据库""造数""查表结构"就会命中）。四条硬性要求：

1. **连库前问清四件事**：哪个系统 / 库地址 / 共享还是本地 / 只读还是造数 —— 不问清楚不许连。
2. **连上先自证没连错**：跑 `select current_database(), host(inet_server_addr()), ...` 与用户说的逐项对照
   —— 最常见的事故是"以为连远程，其实是本地副本"。
3. **全量扫描表结构与关联** → 落 `{{PRODUCT_DIR}}\_库结构\<host>-<dbname>\`。
   注意：**很多业务库没有任何外键约束**，关联只能靠推断 + 业务口径，造数顺序要额外小心。
4. **造数前先查"本次版本"的造数逻辑**（顺序别搞反）：**① 本版规范** `<模块>\skill\<版本>\SKILL.md` **§V4** →
   **② 模块索引** `<模块>\SKILL.md` **§8 版本索引** → **③ 模块 `final\`/`scripts\`** → **④ `_archive\scripts\`**。
   四处都没有才算"没有"。有就照做，没有就**停下来问用户**（不许自己编），

### 跨模块能力 · 看着页面操作流程（playwright MCP，**必用**）

**触发词**：**「我看着你操作」**「看着走一遍流程」「演示一下」「边点边讲」「让我看着页面流程」——
**任何表达"人要看着浏览器里真实发生什么"的诉求**。

**硬性要求：一律用 playwright MCP（`mcp__playwright__browser_*`）打开浏览器并操作真实页面元素。** 不是"可以用"，是**必须**：

| 动作 | 用什么 |
| --- | --- |
| 打开页面 / 跳转 | `browser_navigate` |
| 点按钮 / 切 tab / 进详情 | `browser_click`（**真实鼠标点击**，不是派发事件） |
| 填输入框 / 查询条件 | `browser_type` / `browser_fill_form` |
| 下拉选择 | `browser_select_option`（自绘下拉先点开再用 ref 点选项） |
| 看当前页无障碍树（比截图更准） | `browser_snapshot` / `browser_find` |
| 留下可回看的画面 | `browser_take_screenshot` |
| **看这一屏到底长什么样** | **截图后用 `read_image` 自己读一遍**（见下一节「看图识图」——**不读图 = 漏检**） |
| 控制台报错 / 接口清单 | `browser_console_messages` / `browser_network_requests` |

**边界（照实说，别含糊）**：

- **不许用替代品冒充**：只 `browser_evaluate` 读 DOM、只 `kw_expect_response` 抓报文、只写 py 脚本离线跑、
  只贴一张老截图 —— 这些**都不算"看着操作"**，用户看不见过程就等于没做。
- **点击优先 playwright，取证优先 kw**：自绘组件（uni-app / el-select 等）实测 `kw_click` 常点不动，
  **playwright 真实点击可直接点动**；反过来接口报文自动落盘与 toast 历史是 kw 的强项。两者互补。
- **浏览器窗口可见是前提**：playwright MCP 必须**有头**（去掉 `--headless`），否则"看着"是假的；
  配置改动在 DSH profile 的 `cordis.patch.yml` 里，**改完要重启 DSH 才生效**。
- **一次一步**：看着操作的场景不要连甩十个动作 —— 每步说清"在点什么、预期是什么"，再执行下一步。

### 跨模块能力 · 看图识图（框架级 skill `vision-read`）

**自动加载**（说"看这张图""识别图中文字""截图里写了什么""**截图校验/UI 还原度/布局错位**""这个图表/设计稿/弹窗是什么"就会命中）。

⚠️ **模型已原生具备视觉能力**（框架自带 `read_image`，**秒级、无外部依赖**）：这是**首选通道**；
网页版识图桥保留为**备用 + 交叉核对**（慢、单并发、且实测会整段丢字）。
开关在 DSH profile 的 `cordis.patch.yml` 里 provider 模型的 `input: [text, image]`（**删掉即关闭原生识图**）。

**一条铁律：该看图就必须看 —— 不读图 = 漏检。** "能查到的地方就别读图"依然成立，但反过来也成立：

| 场景 | 动作 |
| --- | --- |
| **playwright（或 kw）走完一屏** | **截图后自己读一遍**（`read_image`），再决定下一步 —— 不许只存档 |
| **UI 还原度 / 布局**（错位、重叠、遮挡、截断、列宽、换行、颜色、字号、图标） | **只能读图** —— DOM 里这些全是"正常" |
| **需求文档里的原型图 / 设计稿** | 导出图片直接读，与环境页面**逐块对照** |
| **图表 / 曲线 / 大屏指标** | 读**形状、趋势、图例、单位**；**数值回接口或库** |
| **弹窗 / 提示 / 空态文案** | 读文案逐字比对（小字先放大或切图） |
| **改前 / 改后回归** | 两张图一起读，直接做差异对比 |
| 元素文本 / 接口报文 / 库值 / 日志 | **仍走 DOM / kw 报文 / `db-seeding` SQL / 日志**（更快更准更可复现） |

**事实分级（报告里怎么用图）**：**视觉事实**（显没显示、位置、遮挡、颜色、图形）→ **截图即证据**；
**文本事实** → 读图初判 + **回 DOM 复核**；**数值/编码事实**（金额、数量、单号、ID、图表数值）→
**一律回 DOM / 接口报文 / 日志 / SQL**，图只作旁证。报告里写清**依据通道**。

### 跨模块能力 · 需求文档读取与「划掉项」核对（框架级 skill `requirement-docs`）

**自动加载**（说"读需求文档""测某系统的某个需求文档""需求方案/需求原文在哪""文档密码是多少""加密 docx 打不开""文档里划掉的部分""下个版本的新需求"就会命中）。

**文档位置**：**所有系统**的需求文档（原始需求 + **下个版本的新需求**）都在**同一个总根目录**下 ——
`{{REQ_DOC_ROOT}}\`，**一个子目录 = 一个系统**；**密码见 §四 指向的 `{{PRODUCT_DIR}}\_框架配置\环境与账密.md`**（**不写在本文件里**）。
**"划掉的不读、但要查"这条规矩对所有系统公用**，不是某个产品的私规。

> ⚠️ **路径不随版本变** → 每次都要先确认"这次看的是哪一版"：
> ① 先看版本升级清单目录里的最新版本号 → ② 顶层无版本号文档 vs `<版本>betaN版本需求方案\`（子目录 = 该批次冻结子集/下个迭代增量）→
> ③ `各版本方案备份\` 是历史备份，**别当最新**（它的 mtime 可能反而更新，**别用时间判版本**）→ ④ 仍不确定就**问用户**（版本判错，后面全白干）。

**五条硬性要求**（⓿ 是"只知道系统+文档名"时的第一步）：

0. **先定位，别猜路径**：用户只说"测某系统的某需求文档"时，跑
   `python skills\requirement-docs\scripts\find_req_doc.py --query "<关键词>" --system <系统>`（`--list` 看有哪些系统），
   或直接用主入口的 `--system <系统> --find "<关键词>"`。
   脚本会列出**全部同名候选**并标注"主线 / 版本子目录 / 历史备份 / 草稿"，**默认取主线那份**；
   **选哪份要写进报告**。找文档时自动挡掉三类假文档：`~$` Word 锁文件、`.svn\`（总根目录可能是 SVN 工作副本，`.svn-base` 不是文档）、**0 字节壳文件**。
1. **原文只读**：解密件与抽取物落模块 `data\需求测试-<yyyyMMdd>\`（`req_src\` 原文副本 / `req_decrypted\` 解密件 / `text\` 正文），
   **不许写回 `requirement\`**（那会让"业务方原文"和"AI 解密件"混在一起）。
2. **先解密再读**：加密与否按 `is_encrypted()` 判，**不看扩展名**（实测 `.doc` 可能是 OLE 但**未加密**；
   **同一系统里加密与明文混着放**，不能按系统一刀切）。一条命令出全部产物：
   `python skills\requirement-docs\scripts\prep_requirement.py --system <系统> --find "<关键词>" --module <模块> --password <密码> --version <版本>`
   （已知确切路径就换 `--src "<文档或目录>"`）
   —— 脚本**自带解释器自举**（bundled python 没装解密库时会自动换本机 python 重跑，看到 `[自举]` 属正常；**别去 pip 装**，本机 pip 下载可能挂住）。
3. **删除线 / 修订删除 = 需求已取消 → 不当需求读**：`w:strike`（单）、`w:dstrike`（双）、段落/样式层删除线、`w:del` 修订删除**四种全覆盖**；
   **整段、整张表被划掉也算取消**。**不许拿划掉的内容当"应该有的功能"去提缺陷**。
4. **但划掉的必须回头核**：脚本会另出一份「取消项核对表」（`取消项核对表-<文档>.md`），**逐项到测试环境确认系统里是不是也去掉了**：

| 环境结论 | 含义 | 后续动作 |
| --- | --- | --- |
| `已同步取消` | 环境里确实没有该入口/字段/枚举/表 | 记下证据路径，不提单 |
| **`未取消（残留）`** | **环境里还留着**（入口/字段/枚举/接口/数据） | **提缺陷**：写清"哪一版哪一块划掉了它" + "环境哪里还在" + 证据 |
| `无法判定` | 没权限 / 环境没这模块 / 判据不明 | **写明缺什么**交给用户定，**不许含糊成"通过"** |

核对通道（按"这功能在哪儿"选，别只挑一个）：**页面** → playwright MCP（要人看着操作时**必须**用）；
**接口** → `keyword_mcp` 报文落盘；**库** → `db-seeding` 只读 SQL（**整表/整列被划掉时，最省的判据是查 `information_schema`**）。

产物落 `<模块>\report\<模块>-取消项核对-<yyyyMMdd>.md`（含逐项表 + 未取消清单 + 证据路径）。

## 六、归档区

`_archive\` 分三块：`scripts\`（历史脚本，体积很小）、`backups\`（体积最大，可清理）、`outputs\`（一次性产出）。

⚠️ **`scripts\` 不能删** —— 里面是各模块**已有的造数/验证/修补脚本资产**（`gen_*` / `fill_*` / `scale_*` / `verify_*` /
`clean_*` / `fix_*` / `diag_*` / `inspect_*`），各模块 `SKILL.md` §8 都指向它们。**删了就得重新问人。**

可以清理的是 `backups\` 里的普通备份，**但有两类不能删**：
- **改名/整改快照** —— 是"改了什么"的唯一证据；
- **升级验证基线**（`*baseline*` / `*expected*` / `*backup*` / `*snapshot*` 一类）—— 是**升级前**推算的，
  升级后**不可重算**，删了这次升级就没法验证。→ 删 `backups\` 前**先按文件名筛一遍 `upg_` / `baseline` / `snapshot` 看一眼**。

⚠️ 归档脚本里**很多把账密写死在代码里** —— 复用前先把连接参数改成命令行传入，不要原样搬进模块。
⚠️ **别用文件时间判断版本**：归档时大量脚本的 mtime 可能被统一写成同一天 —— 判"最新"要**按文件名后缀**
（`_v2` > 无后缀、`_fixed`/`_2`/`_b` > 无后缀、`_retry` > `_fast`）。

### 报告回收（满 24h 自动归档）

Windows 计划任务（或插件/框架提供的等价机制）每小时跑一次 `{{PRODUCT_DIR}}\_冒泡测试\archive_reports.py`，
把**修改时间超过 24 小时**的报告与证据移走：

| 搬什么 | 从哪 | 到哪 |
| --- | --- | --- |
| `<模块>\report\*.md`（**常驻文档除外**） | 各模块 `report\` | `_archive\报告归档\<模块>\<日期>\` |
| 对应的 `<模块>\data\冒泡测试-*\` / `需求测试-*\` | 各模块 `data\` | 同上 |

- **口径**：范围是 `report\` 下的**报告**（不只是冒泡报告）；归档根是 `_archive\报告归档\`。
  判定规则：**文件名以 `_` 开头 = 常驻文档（跳过）**；**含 8 位日期 或 以 `冒泡测试-` 开头 = 归档**；其余按常驻文档跳过。
  `--all` 强制全搬；`--dry-run` 逐条打印跳过原因。

### 闸门：登记不完整时不许直接开测

- `{{PRODUCT_DIR}}\_框架配置\框架登记.json` 的 `gates` 段记录着**完整度检查项**（全部为 `true` 才算过闸）：

  | --- | --- |
  | `documentsRegistered` | 需求文档已登记进 `需求文档台账.md` |

  | `splitConfirmed` | 模块拆分已与用户确认（**一个模块 = 一个顶级菜单**） |
