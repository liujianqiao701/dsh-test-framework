## §0 三条铁律

| # | 铁律 | 要点 |
| --- | --- | --- |
| ① | **该看图就必须看 —— 不读图 = 漏检** | 早先"读图是最后手段"的口径**作废**（那是没有视觉能力时的将就）。**凡"长什么样"才算数的问题，读图是必须动作，不是可选动作。** |
| ② | **事实分级取证**（§2） | 图证明"长什么样"，报文 / 库 / DOM 证明"到底是什么值" |
| ③ | **写清依据通道** | 报告里每一条结论都要写它来自图、DOM、接口还是 SQL |

> **模型已原生具备视觉能力**：框架自带 **`read_image`**（本地图片路径直接喂给模型视觉），
> **秒级、无外部依赖、无并发限制** —— 这是**第一通道**。
> 千问桥 `qvb` **保留但降级为备用 + 交叉核对**：它 15–30 秒/张、单并发，且实测会整段丢字。
> 完整用法与故障阶梯见本机完整版 skill（若已安装）。

## §1 测试中「必须读图」的清单

| 场景 | 为什么非读图不可 | 怎么做 |
| --- | --- | --- |
| **浏览器每走完一屏** | 只看 DOM 会漏掉"渲染出来是什么样" | **截图后自己读一遍再决定下一步**，**不许只存档** |
| **UI 还原度 / 布局**（错位、重叠、遮挡、截断、列宽、换行、颜色、字号、图标） | **DOM 里这些全是"正常"**，只有像素能证明 | 截图逐块读图；必要时与设计稿/原型图并排比对 |
| **需求文档里的原型图 / 设计稿** | 需求常把界面图当验收标准 | 导出图片**直接读**，与环境页面**逐块对照** |
| **图表 / 曲线 / 大屏指标** | 形状、趋势、图例、单位、标注位置只在图里 | 读**图形与标签**；**数值回接口或库**（铁律 ②） |
| **弹窗 / 提示 / 空态文案** | 文案对不对是需求项 | 读图取文案逐字比对；小字**先放大或切图再读** |
| **按钮 / 开关 / 选中态** | "看起来禁用"和"实际 disabled"是两件事 | 图看视觉态 + DOM 看真实属性，**两边都要** |
| **改前 / 改后回归** | 修完有没有引入新的视觉问题 | **两张图一起读**，直接做差异对比 |
| **别人发来的图 / 客户截图 / 扫描件** | 本机没有别的通道 | 直接读；结论仍按 §2 分级 |

**反例（别浪费一次读图）**：页面上某元素的文本 → 回 DOM 取值；接口返回 → 抓报文；
库里值 → 只读 SQL；程序报错 → 日志。

## §2 证据分级（**报告里怎么用图，按这张表**）

| 事实类型 | 图能当证据吗 | 落报告怎么写 |
| --- | --- | --- |
| **视觉事实**：显示/隐藏、位置、遮挡、截断、颜色、字号、图标、图表形状 | ✅ **可以，截图即证据** | 贴截图 + 一句"**读图**取自 `<截图路径>`" |
| **文本事实**：菜单名、字段名、按钮文案、提示语 | ⚠️ 只作**初判**；要**逐字引用**必须**回 DOM 复核** | "读图初判 + DOM 复核"两条都写 |
| **数值事实**：金额、数量、库存、比例、单号、ID、时间、图表数值 | ❌ **不可只凭读图**（图上是像素，读数会有误差） | 必须给**接口报文 / SQL 结果 / DOM 取值**的路径；图只作**旁证** |
| **结论**：通过 / 不通过 / 残留 | —— | 写清**依据通道**；只靠读图下的结论要标注"未经回源核实" |

> 一句话：**图证明"长什么样"，报文 / 库证明"到底是什么值"。** 两者都要时，两个路径都写进报告。

## §3 怎么读（按"你要什么"选）

| 你要什么 | 怎么做 |
| --- | --- |
| **我自己看图（默认）** | 框架工具 `read_image`（传本机图片路径）—— 秒级 |
| 要第三方复读 / 交叉核对 | 千问桥 `qvb`（**备用通道**，见 §4） |
| 页面取证 + 真实操作 | playwright MCP 截图 + 操作，**每屏截图后自己读** |
| 接口 / DOM / 库取证 | playwright `browser_network_requests`（接口）/ `browser_snapshot`、`browser_evaluate`（DOM）/ `db-seeding` 只读 SQL |

- **读之前先想清楚要看什么**：与其"描述这张图"，不如带着问题读 ——
  「这个表格第三列的数值是多少」「这个报错弹窗的标题是什么」「按钮是不是被右边缘截断了」。
- **小字 / 密字先放大或切图**：整屏 1920×1080 直接读，右下角小字最容易读错。
- **拿到"戛然而止"的读法时，先怀疑图被裁了**，而不是先怀疑自己读漏了。

## §4 备用通道：千问桥 `qvb`（**不要写成首选**）

- 定位：**原生 `read_image` 不可用时**，或**要第三方复读一遍做交叉核对**时才用。
- 已知边界：**15–30 秒/张、单并发**；**读全文字截图会整段丢字**（实测 401 字丢 4 处，换提示词重读丢失位置一样）→
  **不能拿到"逐字引用"的信任级别**；但**干净的纯文字 / 表格截图很准**（实测表格里 20 个编号全部一致）——
  **规律是"样式越花、字越密越要交叉核对"，不是"它一定读错"**。
- ⚠️ 它**不会告诉你图被截断了**：读到末尾突然断句，先怀疑图被裁。
- ⚠️ **`engine\profile\` 是登录 cookie**：不入库、不外传；`engine\node_modules\` 也不是资产，可重建。
- 桥的启停、故障阶梯、切官方 API 的做法 → **见本机完整版 skill**（若已安装）。
