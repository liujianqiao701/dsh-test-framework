## §0 四条硬性要求

1. **原文只读**，且**先确认是哪一版**（§1、§2）—— 版本判错，后面全白干。
2. **加密文档一律先解密**，脚本内不留密码（§3）—— 直接打开报错；密码落进报告就是凭据外泄。
3. **删除线 / 修订删除 = 需求已取消，不当需求读**（§4）—— 不许拿划掉的内容当"应该有的功能"去提缺陷。
4. **取消项单独出清单，逐项到环境核对**（§5）—— 环境里还留着的残留项全在这一步暴露。

> 一句话：**划掉的不读，但要查**。读的是"该有什么"，查的是"该没有的有没有真的没有"。**这条规矩对所有系统公用**，不是某个模块的私规。

## §1 文档在哪 + 怎么定位

- **总根目录** `{{REQ_DOC_ROOT}}`（**一个子目录 = 一个系统**：`系统A` / `系统B` / `系统C` … 有几个系统就有几个子目录）。
- 用户只说「测某系统的某需求文档」时 → **自己去总根目录定位**（按系统子目录 + 文件名关键词、编号比对），**不许凭记忆猜路径**；命中多份时按 §2 选。
- **必须挡掉三类假文档**：

| 假文档 | 现象 | 处置 |
| --- | --- | --- |
| **`~$xxx.docx`** | Word 打开时生成的锁文件（内容就是用户名，几百字节） | 跳过 `~$` 开头的，它不是文档 |
| **`.svn\`（含 `.svn\pristine\**\*.svn-base`）** | 总根目录是 SVN 工作副本的内部原始副本 | 跳过整个 `.svn\` |
| **0 字节 docx** | 检出 / 同步没完，或被人清空 | `getsize()==0` 直接跳过；**别当成"加密打不开"** |

> ⚠️ **加密与明文混着放**（同一系统里两种都有）→ **逐个文件按内容判加密与否**，不要按系统一刀切，**也不要看扩展名**（实测 `.doc` 可能是 OLE 但并未加密）。

## §2 先确认是哪一版（**路径不区分版本**，用前必判）

| 规则 | 说明 |
| --- | --- |
| 顶层无版本号文档 | 通常是**当前最新版主线** |
| 版本升级清单目录 | **判"这版改了什么"先看这里**（拿最新版本号） |
| `<版本>betaN版本需求方案\` 等子目录 | 该批次的**冻结子集** / 下个迭代增量 |
| `各版本方案备份\` / `备份\` / `草稿\` | 历史备份与草稿，**别当最新** |
| 同名文档出现多份 | **默认取主线**那份，并在**报告里写明依据路径**；用户点名版本才用子目录那份 |

> ⚠️ **不许用文件时间判版本** —— 备份 / 检出会让 mtime **反而更新**（实测备份里那份比主线还新）。
> 定位候选要**逐个标注身份**：「主线 / 版本子目录 / 历史备份 / 草稿」，默认取主线。
> 三步判版本：① 看升级清单里最新版本号 → ② 比顶层与版本子目录同名文档的**内容差异** → ③ 仍不确定就**问用户**。

## §3 加密文档先解密（别手点 Word）

- **加密与否按内容判**，不按扩展名；加密件用常规 Office 库直接打开会报 `Package not found` / `BadZipFile`。
- 解密密码**见产品级规范** `{{PRODUCT}}\_框架配置\环境与账密.md`（**唯一出处**）：调用时临时传入，**脚本内不留密码**，报告里也不写密码。
- **解密件不要写回 `requirement\`**（那是"业务方原文"的位置，混在一起就分不清哪份是原文）；解密件与抽取物统一落 `<模块>\data\需求测试-<yyyyMMdd>\`（`req_src\` 原文副本 / `req_decrypted\` 解密件 / `text\` 正文）。
- **OLE ≠ 加密**：先探测再解，对明文文件硬套解密会抛 `File is not encrypted`。
- 原文件被 Word 占用时，用脚本 / 库读通常仍可行；读不了先换读法，别急着让用户关 Word。

## §4 划掉 = 取消（四种形态，缺一个就把废弃内容当需求）

| 形态 | XML / 位置 | 说明 |
| --- | --- | --- |
| 单删除线 | `w:strike` | 最常见的"横线划掉" |
| 双删除线 | `w:dstrike` | Word 的"双删除线"，**也是划掉** |
| 段落 / 样式层删除线 | 段落 `pPr/rPr`、`p.style.font.strike` | 整个标题 / 整段被划掉；**只查 run 会漏** |
| 修订删除 | `w:del` 里的 `w:delText` | 修订模式下删掉的字，接受修订后就消失 —— **等价于取消** |

> ⚠️ **整段、整张表被划掉也算取消**（实测有整张表连标题 + 表头 + 字段全被划掉，并标注了「【某版本删除】」）。
> 这种情况的核对结论是**该表 / 该字段在环境里不该存在**，不是"页面少个按钮"。

## §5 取消项核对：**划掉了 → 环境里是不是也去掉了**（本规范的核心）

先归类"这条划掉项该消失在哪里"，再选通道：

| 划掉的内容 | 该去哪儿核 | "也去掉了"长什么样 |
| --- | --- | --- |
| 菜单 / 页面 / 按钮 / Tab | **页面**（playwright MCP，真实点击） | 进该模块**没有**该入口；截图 + DOM 取值 |
| 列表字段 / 列 / 表单项 | **页面 + 接口** | 页面无该列；接口响应**不返回**该字段 |
| 枚举值 / 下拉项 / 单选项 | **页面 + 接口 + 库** | 下拉无该选项；字典不返回；字典表无该值 |
| 校验规则 / 计算逻辑 | **页面实测 + 接口** | 构造触发条件，行为按新规则 |
| 后台表 / 表字段 | **库**（`db-seeding` 只读 SQL） | 表或列**不存在** |
| 报表指标 / 统计口径 | **页面 + 接口 + 库** | 报表无该指标；接口无该字段 |
| 仅文案变化 | **页面** | 页面上是**新文案**，旧文案搜不到 |

**三条取证通道（按"这功能在哪儿"选，别只挑一个）**：**页面** → playwright MCP（用户要"看着"时必用）；**接口** → `keyword_mcp` 报文落盘；**库** → 只读 SQL（连上先用 `host(inet_server_addr())` 自证没连错）。

> ⚠️ **整表 / 整列被划掉时，最省的判据是查 `information_schema`**（`information_schema.tables` / `.columns`）—— 一次 SQL 就能证明"该表 / 该列在环境里到底还在不在"，比翻页面快得多。

**结论只有三种，必须逐项落**：

| 结论 | 含义 | 后续动作 |
| --- | --- | --- |
| `已同步取消` | 环境里确实没有该入口 / 字段 / 枚举 / 表 | 记下证据路径，不提单 |
| **`未取消（残留）`** | **环境里还留着**（入口 / 字段 / 枚举 / 接口 / 数据） | **提缺陷**：写清"哪一版哪一块划掉了它" + "环境哪里还在" + 证据 |
| `无法判定` | 没权限 / 环境没该模块 / 判据不明 | **写明缺什么**交给用户定，**不许含糊成"通过"** |

## §6 落位与快速清单

```
<模块>\report\<模块>-取消项核对-<yyyyMMdd>.md    核对结论（逐项表 + 未取消清单 + 证据路径）
<模块>\data\需求测试-<yyyyMMdd>\                 原文副本 / 解密件 / 正文 / 划掉清单 / 截图 / 报文
```

报告**必须写清**：需求文档路径 + **版本** + 抽取时间 + 每项的**依据通道**（划掉项随版本变，缺版本号结论无法复现）。

```
□ 1. 确认是哪个系统 → 在 {{REQ_DOC_ROOT}} 下定位到具体文件（不许猜路径），命中多份取主线并写明依据
□ 2. 确认这一版是哪一版（升级清单 → 内容差异 → 问用户）；不许用文件时间判版本
□ 3. 挡掉三类假文档：~$ 锁文件 / .svn\ / 0 字节壳
□ 4. 加密的先解密（密码见 {{PRODUCT}}\_框架配置\环境与账密.md，脚本内不留密码），解密件落 data\ 不落 requirement\
□ 5. 正文（跳划掉）通读 → 作为需求口径；划掉项另出清单 → **不算需求**
□ 6. 逐项到环境核对（页面 / 接口 / 库三通道）→ 已同步取消 / 未取消（残留）/ 无法判定，**逐项落**
□ 7. 残留项提缺陷；无法判定写明缺什么，**不许含糊成通过**
□ 8. 报告落 <模块>\report\，写明路径 + 版本 + 抽取时间 + 依据通道
```
