## 这个框架解决什么

以前每次开新会话，AI 都要重新问一遍"环境在哪、账密是什么、上次怎么测的"，历史脚本和测试数据散落在根目录里越积越多；需求文档在哪个目录、是哪一版、密码是什么，也全靠人记。
现在：

- **新会话自动读根目录的 `AGENTS.md`** → 开工顺序、铁律、模块路由、环境与账密的**去处**全都知道；
- **每个模块有自己的文件夹和 skill** → 需求、整理稿、报告、数据各归其位，不再混在根目录；
- **产品级规范集中在 `{{PRODUCT_DIR}}\_框架配置\`** → 环境与账密 / 需求文档台账 / 模块路由 / 框架登记，一个地方登记、全框架统一引用（**账密不进 `AGENTS.md`、不进脚本、不进报告**）；
- **需求文档规矩固化** → 全部系统的文档都在总根目录 `{{REQ_DOC_ROOT}}\`，**划掉的不读、但要回头核**；
- **冒泡测试按模块拆分** → 一个模块一份独立报告、一份独立 data，**满 24 小时自动归档**，新旧批次不互相覆盖；
- **模块规范按版本分开** → `<模块>\SKILL.md` 是**索引**，`<模块>\skill\<版本>\SKILL.md` 是**该版本的规范**，一版一份、多版并存、互不覆盖（**不要把多个版本融进一份**）；
- **测试报告怎么写有硬要求** → 结论先行 + 缺陷速览表在最前、一条缺陷一小节（≤20 行）、复现步骤可照做、**每条必须写「需求原文依据」与「与需求不符点」**；
- **登记不完整就不许开测** → 新需求文档先走插件的引导流程 `test-framework-onboard`，把版本、模块、环境登记齐了再动手。

│       ├── data\           测试数据/素材/证据（按需建）

## 常用操作

**初始化框架**：插件工具 `test_framework_init`（或按插件 README 的 CLI）在本目录落框架骨架 ——
生成 `AGENTS.md` / `README.md` / `skills\` / `.dsh\skills` 联接 / `.git\` 标记 / `_templates\` / `_archive\`，
并建立 `{{PRODUCT_DIR}}\_框架配置\`。落完先跑一次登记（见下一条）。

**登记新需求文档（开工引导）**：新需求文档一律先走插件内嵌 skill **`test-framework-onboard`**：
定位文档（`find_req_doc.py --list` / `--query`）→ **确认是哪一版** → 拆模块 → 登记环境与账密 →
建模块骨架 → 在 `AGENTS.md` §三 与 `_框架配置\模块路由.md` 登记。
**闸门**：`_框架配置\框架登记.json` 里有缺项时**不许直接开测**。

**跑冒泡测试**：直接说「**测试 {{PRODUCT}} 的冒泡测试**」→ 读 `{{PRODUCT_DIR}}\_冒泡测试\冒泡测试规范.md`（首次用到时建立）。
它会**先问你账号密码、数据库地址，以及本次测哪个模块**，然后预检环境 → 逐页遍历（页面/列表/接口/按钮都点一遍）→
模拟用户增删改查 → 连数据库核对 → 把每条页面报错/接口报错/阻塞记进报告，并定位到「模块 → 页面 → 列表 → 按钮 → 操作」。
**一个模块 = 系统里一个叶子菜单 = 一份独立报告 + 一份独立 data**（多模块就出多份，不合并）；
报告与证据**满 24 小时由归档任务自动移到 `_archive\报告归档\<模块>\<日期>\`**。

**连数据库 / 造数**：框架级 skill **`db-seeding` 自动加载**（说"连数据库""造数""查表结构"就命中）。它会：
① 先问你**是哪个系统**并核对库地址（连上跑 `host(inet_server_addr())` 自证没连错机器）；
② 全量扫描表结构与关联关系，落 `{{PRODUCT_DIR}}\_库结构\`（很多业务库**没有外键约束**，关联靠推断 + 业务口径）；
③ 造数前按这个顺序找**本次版本**的造数逻辑：
**① 本版规范** `<模块>\skill\<版本>\SKILL.md` **§V4** → **② 模块索引** `<模块>\SKILL.md` **§8 版本索引** →
**③ 模块 `final\`/`scripts\`** → **④ `_archive\scripts\`** —— 四处都没有才算"没有"
（**没有 `<版本>-造数逻辑.md` 也不代表没有** —— 有的模块用 `final\<模块>造数维护文档.md` 这种别名，**以 §8 的指向为准**）。
**有就照做，没有就停下来问你**，拿到后写 `final\<版本>-造数逻辑.md` 并**回填该版规范 §V4 + 索引 §8**；
④ 主键用 `next_key.py` 动态侦测，不写死。

**读需求文档 / 文档里被划掉的部分**：框架级 skill **`requirement-docs` 自动加载**。
**所有系统的需求文档都在同一个总根目录** `{{REQ_DOC_ROOT}}\`（**一个子目录 = 一个系统**），常见是加密 docx/xlsx，
**密码见 `{{PRODUCT_DIR}}\_框架配置\环境与账密.md`**（**不写进脚本、不写进报告**）；**新版本需求也放同一目录**，所以用前先判是哪一版。

```powershell
# 先看总根目录有哪些系统、各有几份（含加密/明文统计）
python skills\requirement-docs\scripts\find_req_doc.py --list

# 一步到位：定位 + 解密 + 抽正文 + 出取消项核对表
python skills\requirement-docs\scripts\prep_requirement.py `
       --system <系统> --find "<关键词>" --module <模块> --password <密码> --version <版本>
# 已知确切路径就换：--src "<加密文档或目录>"
```

定位会列出**全部同名候选**并标注"主线 / 版本子目录 / 历史备份 / 草稿"（**默认取主线那份，依据要写进报告**），
自动挡掉三类假文档：`~$` Word 锁文件、`.svn\`（总根目录可能是 SVN 工作副本）、**0 字节壳文件**；
**不许用文件时间判版本**（备份的 mtime 可能比主线还新）。

**规矩（两条，别搞混）**：① **划掉的内容 = 需求已取消，不当需求读**；
② **但划掉的必须回头核**：逐项到测试环境确认「**系统里是不是也去掉了**」——
环境里也没有 = 合规；**环境里还留着 = 残留，提缺陷**；查不了 = `无法判定` 并写明缺什么。
核对走 **页面（playwright MCP）/ 接口（keyword_mcp 报文落盘）/ 库（db-seeding 只读 SQL）** 三条通道。

**看着页面操作流程**（说"我看着你点""看着走一遍流程""演示一下"）：**必须用 playwright MCP**
（`mcp__playwright__browser_*`）**打开浏览器 + 真实操作页面元素**（导航/点击/输入/切 tab/翻页），逐屏推进并同步解说。
**不许拿"只读 DOM / 只抓报文 / 只跑脚本 / 只贴截图"冒充** —— 用户看不见过程就等于没做。
纯取证（接口报文落盘、toast 历史）仍走 `keyword_mcp`，**两者互补不替代**。

**看图片 / 识别图中文字**：框架级 skill **`vision-read` 自动加载**。
模型**原生能看图**（框架自带 `read_image`，秒级、无外部依赖），**该看图就必须看 —— 不读图 = 漏检**：

| 场景 | 动作 |
| --- | --- |
| 浏览器走完一屏 | **截图后自己读一遍**，不许只存档 |
| UI 还原度 / 布局（错位、遮挡、截断、颜色、图标） | **只能读图**（DOM 里这些全是"正常"） |
| 需求文档里的原型图 / 设计稿 | 导出图片直接读，与环境页面逐块对照 |
| 图表 / 大屏指标 | 读形状、趋势、图例、单位；**数值回接口或库** |
| 弹窗 / 提示 / 空态文案 | 读文案逐字比对（小字先放大或切图） |
| 改前 / 改后回归 | 两张图一起读，直接做差异对比 |
| 元素文本 / 接口 / 库值 / 日志 | **仍走 DOM / kw 报文 / SQL / 日志**（更快更准更可复现） |

**事实分级（报告里怎么用图）**：视觉事实 → **截图即证据**；文本事实 → 读图初判 + **回 DOM 复核**；
**数值/金额/编码/单号/图表数值 → 一律回 DOM / 接口 / 日志 / SQL**。网页版识图桥保留为**备用 + 交叉核对**。

**写测试报告**：套 `_templates\测试报告模板.md`，落到**对应模块**的 `report\`，
命名 `<模块>-<内容>-<yyyyMMdd>.md`（跨模块问题就每个受影响模块各写一份）。**写法是硬要求**（要求"一目了然，不要密密麻麻一大长篇"）：

| # | 要求 |
| --- | --- |
| ① | **结论先行** —— §一 结论 + **§二 缺陷速览表放在最前**（每条一句话说清哪儿不对 + 严重级 + 需求依据 + 状态） |
| ② | **一条缺陷一小节**，字段固定、**每条 ≤ 20 行**，禁止把多条揉成一段 |
| ③ | **复现步骤清晰可照做** —— `1. 2. 3.` 每步一行（打开什么 → 输入点什么 → 看到什么） |
| ④ | **每条缺陷必须写「需求原文依据」**（文档名 + 章节号 + **原文引用**）与**「与需求不符点」**（单独一行点明差在哪个字段/分支/文案/口径）；需求确实没写的写 `需求未明确` |
| ⑤ | 大段日志 / 接口报文 / SQL 结果**不进正文**，落 `data\` 只写路径 |
| ⑥ | 含**结论 + 证据 + 我改过什么/是否还原** |

**报告回收（满 24h 自动归档）**：脚本 `{{PRODUCT_DIR}}\_冒泡测试\archive_reports.py`（计划任务每小时跑一次）。
范围是 `report\` 下的**报告**（不只冒泡报告），归档到 `_archive\报告归档\<模块>\<日期>\`；对应的 `data\冒泡测试-*\` / `需求测试-*\` 一并搬。
判定：**`_` 开头 = 常驻文档（跳过）**；**含 8 位日期 或 `冒泡测试-` 开头 = 归档**；其余跳过（`--all` 强制全搬）。
插件入口 **`test_framework_report_gc`**（默认 `dryRun:true` 只看不动），它只是去找并调用那份 python 脚本 —— **归档逻辑只有一份实现**。
手动跑：`python archive_reports.py --dry-run` / `--hours 48` / `--all` / `--backfill-index`。

**新增模块**（**推荐直接用插件工具 `test_framework_module_add`**，它把下面 6 步一次做完，**记得传 `version`**）：

1. 建 `{{PRODUCT_DIR}}\<模块名>\`（**不要用 `_` 开头**）；
2. 建 `requirement\`、`final\`、`report\`（要存数据/素材再建 `data\`，有专属脚本再建 `scripts\`）；
3. 复制 `_templates\模块骨架\SKILL.md` 为 `<模块名>\SKILL.md`（**索引**）；
4. 建 `<模块名>\skill\<版本>\`，复制 `_templates\模块骨架\skill\版本骨架\SKILL.md` 进去（**该版规范，一版一份**）；
5. 填索引 §1 定位 / §2 数据来源 / §3 测试要点 / §4 坑 / §7 冒泡测试（**把"系统菜单/路由"填上**）/
   **§8 版本索引**（一行一个版本 → 指向 `skill\<版本>\SKILL.md`）/ §9 划掉项核对；
   再填该版 §V1 基本信息 / §V2 本版需求范围（新增·修改·**取消**）/ §V3 测试要点 / §V4 造数逻辑 / §V5 坑；
6. 在 `AGENTS.md` §三 **登记一行**，并同步 `_框架配置\模块路由.md`（**不登记 = 会话里读不到它**）。

**skill 放哪层**：跨产品共用 → `skills\`（自动加载）；本产品内跨模块共用 → 产品级 `_框架配置\` / `_<名字>\`；
只在单个模块内成立 → **再分两层**：跨版本的公共约定放 `<模块>\SKILL.md`（索引），**随版本变的**放 `<模块>\skill\<版本>\SKILL.md`。
**不要因为"写得长"就往上放一层；也不要把多个版本揉进一份。**

**环境账密**：统一登记在 `{{PRODUCT_DIR}}\_框架配置\环境与账密.md`，别散落进脚本、模块 `SKILL.md`、报告；
**冒泡测试例外** —— 每次现问。

**归档区**：`_archive\` 分成 `scripts\` / `backups\` / `outputs\`。
⚠️ **`scripts\` 不能删**：里面是各模块**已有的造数/验证/修补脚本资产**，每个模块的 `SKILL.md` §8 都指向它们具体是哪几个。
可以清理 `backups\` 里的普通备份，**但两类不能删**：① 改名/整改快照（"改了什么"的唯一证据）；
② 升级验证基线（`*baseline*` / `*expected*` / `*backup*` / `*snapshot*`）—— 是**升级前**推算的、升级后**不可重算**。
⚠️ 归档脚本**很多把账密写死在代码里**，个别还写死了**已不存在的旧路径** —— 复用前先改这两处，别原样搬进模块。
⚠️ **别用文件时间判断版本**：归档时脚本的 mtime 可能被统一成同一天，判"最新"要按**文件名后缀**。
